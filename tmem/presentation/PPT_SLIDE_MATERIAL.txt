1. TITLE / SUBTITLE OPTIONS
--------------------------------------------------------------------------------
- T-MEM: Temporal Decay for Agent Memory Retrieval
- Extending A-MEM (Xu et al., NeurIPS 2025) with time-aware relevance on top of cosine similarity
- Self-contained Python prototype — no LLM APIs — LoCoMo-style simulation

References:
- Paper: A-MEM: Agentic Memory for LLM Agents — https://arxiv.org/abs/2502.12110
- Codebases (paper): benchmark https://github.com/WujiangXu/AgenticMemory ; system https://github.com/WujiangXu/A-mem-sys

--------------------------------------------------------------------------------
2. PROBLEM STATEMENT (1–2 SLIDES)
--------------------------------------------------------------------------------
- A-MEM stores structured memory notes and retrieves by **embedding cosine similarity** (paper Eq. 8–9): same semantic similarity for old and new memories if text overlaps.
- **Gap:** Long-horizon agents need **recency / staleness**: a memory from months ago should often rank below a newer memory even when both match the query lexically.
- **Our addition (current default):** a **temporal decay** factor on each note, blended with cosine in the retrieval score so newer evidence can surface.
- **Scope:** This repo implements retrieval-time scoring + a reproducible simulation; it does not re-run full LoCoMo with GPT-4o-mini unless you wire that externally.

--------------------------------------------------------------------------------
3. A-MEM BASELINE (WHAT WE PRESERVE)
--------------------------------------------------------------------------------
Memory note (paper Eq. 1): m_i = { c_i, t_i, K_i, G_i, X_i, e_i, L_i }
  c_i = content, t_i = timestamp, K_i keywords, G_i tags, X_i contextual sentence,
  e_i = embedding, L_i = set of linked memory ids.

Embedding (paper): e_i = f_enc( concat(c_i, K_i, G_i, X_i) )
  Implementation: single string = content + space + keywords + space + tags + space + context
  Encoder (paper Sec. 4.2): SentenceTransformer "all-MiniLM-L6-v2"

Retrieval (paper Eq. 9 style): rank by cosine similarity
  s_{q,i} = cos(e_q, e_i)  with L2-normalized vectors (NumPy implementation)

Baseline in code: amem_retrieve() — pure cosine, descending.

--------------------------------------------------------------------------------
4. TEMPORAL DECAY + MODIFIED RETRIEVAL (OUR EXTENSION)
--------------------------------------------------------------------------------
Decay (uses creation time t_i = note.timestamp, NOT last_accessed):

  age = max(0, (t_current - t_i) expressed in chosen time unit)

  decay(m_i) = exp( -lambda * age )

Age unit (config decay_age_unit):
  - "days"     : age = elapsed_seconds / 86400  (literal day count)
  - "months_equiv" (default): age = days / 30  (keeps exp(-lambda*age) meaningful over multi-month gaps when lambda=0.1)

Edge case: if t_current < t_i (note "in the future"), age clamps to 0 → decay = 1.

Default relevance (decay-only mode, use_decay_only_temporal=True — CURRENT DEFAULT):

  r_i = decay(m_i)

Optional full product (use_decay_only_temporal=False):

  reinforce(m_i) = 1 + beta * log(1 + access_count_i)
  link_bonus(m_i) = 1 + gamma * (|L_i| / max_j |L_j|)
  r_i = decay * reinforce * link_bonus

Normalization for blending:

  r_hat_i = (r_i - min_k r_k) / (max_k r_k - min_k r_k)   [min-max over ALL notes in M; flat → 0.5]

Modified retrieval score (same alpha blend as broader T-MEM design):

  score(q, m_i) = alpha * cos(e_q, e_i) + (1 - alpha) * r_hat_i

  alpha = 1  →  exactly cosine-only ranking (recovers A-MEM baseline for ablation)

Default hyperparameters (tmem/config.py):
  decay_lambda (lambda)     = 0.1
  blend_alpha (alpha)       = 0.7
  reinforce_beta (beta)     = 0.5   [ignored when decay-only]
  link_gamma (gamma)        = 0.3   [ignored when decay-only]
  use_decay_only_temporal   = True   [only exp decay in r_i]
  decay_age_unit            = "months_equiv"
  auto_link_cosine_threshold= 0.5   (for simulated graph; links do not affect r_i in decay-only mode)

Evaluation time t_current in simulation: fixed datetime 2025-06-10 12:00 (after last session so all ages >= 0).

--------------------------------------------------------------------------------
5. WHY MIN–MAX r_hat AND NOT RAW DECAY IN THE BLEND
--------------------------------------------------------------------------------
- Raw decay lives in (0, 1]; cosine in roughly [-1, 1] for MiniLM.
- Min–max puts temporal evidence on [0, 1] comparable scale across the bank for the affine blend.
- Trade-off: global min–max can let one dominant note shape r_hat (document in thesis limitations).

8. SIMULATION DESIGN (REPRODUCIBILITY SLIDE)
--------------------------------------------------------------------------------
- 30 memory notes = 3 notes × 10 sessions.
- Session dates: anchored at 2025-01-05 + offsets [0, 15, 32, 50, 67, 85, 92, 98, 108, 125] days (~4 month spread).
- Narrative scenarios baked into text (for cosine + decay stress tests):
  * Job: Google (early) → Meta (later); query “currently work” uses overlapping “currently” wording.
  * Location: NYC/Brooklyn → Seattle / Capitol Hill; address + USPS change.
  * Photography hobby across sessions with higher access_count (only matters if use_decay_only_temporal=False).
  * One-off restaurant recommendation (low access, old).
  * Japan trip planning + follow-up sessions (for linking).
  * Contradictions: old phone vs new phone; old vs new “current” facts.
- Links: undirected; if cos(e_i, e_j) > 0.5 then add each id to the other’s L_i list.
- No generative LLM: metadata is hand-authored to mirror the *fields* A-MEM would fill with an LLM.

13. COSINE SIMILARITY IMPLEMENTATION DETAIL
--------------------------------------------------------------------------------
- Query and note embeddings are float vectors.
- cos(q, row_i) = (row_i · q) / (||row_i|| * ||q||) with epsilon 1e-12 in denominators.
- Full memory scan O(|M|) per query — acceptable for thesis demo; A-mem-sys uses Chroma for scale.

--------------------------------------------------------------------------------
14. LIMITATIONS / HONESTY SLIDES (RECOMMENDED)
--------------------------------------------------------------------------------
- Simulation metadata is **hand-written**, not LLM-extracted like full A-MEM.
- Link creation is **cosine-threshold**, not LLM neighbor selection (paper Sec. 3.2).
- **Decay-only** r_i ignores usage/links unless you set use_decay_only_temporal=False.
- **months_equiv** rescales time vs literal “days” in a written formula — state λ together with the age definition.
- Hash encoder is **not** semantic; only for pipeline testing without HF.
- Top-1 system answer can differ from **best GT rank** (especially single-hop / adversarial) — report ranks, not only argmax id.

17. ONE-SLIDE “EQUATION SUMMARY”
--------------------------------------------------------------------------------
A-MEM:     rank by  cos(e_q, e_i)

Extension: r_i = exp(-λ·age(t_i))     [decay-only default]
           r̂_i = minmax_j(r_j) over bank
           score_i = α·cos(e_q,e_i) + (1-α)·r̂_i

Ablation:  α = 1  ⇒  A-MEM baseline
