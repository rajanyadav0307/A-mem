## 3. How the writing will be done

**Step 1: Fact ledger.**
- A file `docs/thesis/FACT_LEDGER.md` will list every number and factual claim with an ID, the source file (and commit), and how to re-check it.
- A script `thesis_tables.py` recomputes every table from the result files and prints them in final form. If a number in the draft doesn't match the script, the draft is wrong.

**Step 2: Verify the literature.**
- For each paper: open the arXiv or ACL Anthology page, then record the exact title, authors, year, venue and ID in the ledger.
- Use only claims a paper actually makes, with the section or page noted.

**Step 3: Write in order of how checkable each part is.**
1. III Framework and IV Implementation, from the code
2. V Setup, from manifests and data
3. VI Results, from the script
4. VII Discussion, from the analyses
5. II Related Work, from verified papers
6. I Introduction
7. VIII Conclusion
8. Abstract (≤150 words) last

**Step 4: Voice pass on every section.**
- Apply the write-like-human rules and the Wikipedia AI-signs list.
- Apply the manual's rules: single author ("I", never "we"), past and present tense, no future tense for the method.
- Check banned words with a script (grep).

**Step 5: Build the Word file.**
- Edit a copy of the template, so its styles, compatibility mode, footers and fields are kept.
- Fill placeholders with real text, insert tables as Word tables with template captions, add the figure, and fill the references.
- Never change the original template file.

**Step 6: Check.**
- Validate the .docx.
- Render it to PDF and look at every page: margins, page numbers, headings at 2 in, captions, table of contents fields. LibreOffice isn't installed; Microsoft Word is (see questions).
- Re-run `thesis_tables.py` against the final text. Confirm every citation is listed and every listed reference is cited.

**Step 7: Deliver section by section.** I'll show you each chapter as it's done, so you can correct facts early.
